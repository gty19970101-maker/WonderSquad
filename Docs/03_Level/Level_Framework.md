# Level Framework

## 系统目标

提供“一关一张独立小地图”的关卡生命周期、内容加载、目标编排、检查点、恢复点、有限变体和完成结算框架。

首个关卡《沉睡森林》必须在 10～20 分钟内验证角色能力、非语音交流、多种解法、欢乐失败和队友救援。

## 系统边界

负责：

- LevelDefinition 加载与校验。
- 关卡进入、等待、开始、进行、完成、结算和退出。
- 出生点、检查点、恢复点和关键道具恢复点。
- 主目标、子目标和三个机关完成汇总。
- 提供固定小地图边界、背景资源 ID 和世界坐标映射参数。
- 加载固定默认关卡变体；为 MVP 后续的主机种子选择保留数据字段。
- 全队无法互救时的安全恢复。
- 作为复合恢复的唯一 Recovery Orchestrator。
- 测试数据记录。

不负责：

- 具体移动、能力、制作、机关和状态规则。
- 连续开放世界和世界分区。
- 玩家关卡编辑器 UI。
- UGC 上传、下载、评分与审核。
- 长期基地和账号存档。

## 核心流程

```text
房间确认玩家与角色
→ 主机选择 LevelId
→ 加载并校验 LevelDefinition
→ 加载固定 DefaultLevelVariant
→ 加载关卡场景
→ 注册出生点、检查点、机关和目标
→ 生成玩家
→ 等待必要玩家就绪
→ 开始计时
→ 汇总机关和主目标
→ 主机确认完成
→ 结算
→ 卸载关卡并返回选择/房间
```

### 《沉睡森林》主流程

```text
入口与非语音教学
→ 森林资源区
→ 沉睡藤门
→ 回声石阵
→ 古代传送门
→ 完成与结算
```

具体步骤由数据编排，Level 不直接实现机关逻辑。

## 主要状态

### 关卡阶段

- `Unloaded`
- `Loading`
- `Validating`
- `WaitingForPlayers`
- `Playing`
- `Completed`
- `Result`
- `Unloading`
- `FailedToLoad`

### 目标状态

- `Locked`
- `Available`
- `InProgress`
- `Completed`
- `FailedRecoverable`

### 检查点状态

- `Inactive`
- `Active`
- `Current`

关卡阶段由主机转换，并带 Revision 防止客户端应用过期事件。

## 与其他系统的依赖

编译时依赖：

- `Core/Contracts`：关卡命令、领域事件、恢复端口和快照。
- `Content`：LevelDefinition、默认变体、检查点与恢复点。

通过端口或事件协作：

- 订阅 Player、Puzzle、Item 和 Status 的公开事件。
- 使用 PlayerRecoveryPort、ItemRecoveryPort、PuzzleResetPort 和 StatusClearPort。
- 向 Communication 与 UI 发布只读关卡快照和地图边界。
- Network Adapter 复制关卡阶段。
- Save 只接收匿名测试摘要。

任何 Gameplay 领域模块都不反向依赖 Level 实现。

### Recovery Orchestrator

复合恢复是唯一的有序事务：

1. 分配 RecoveryTransactionId 并暂停目标交互。
2. 取消持续交互、救援和持有关系。
3. 恢复关键物品。
4. 局部重置机关并增加 Revision。
5. 清除相关临时状态。
6. 将玩家移动到权威检查点。
7. 恢复交互并发布事务完成。

重复恢复请求必须返回同一事务结果。

## 联机同步要求

- 主机选择关卡并确认固定默认变体。
- 客户端加载相同 LevelId 和内容版本。
- 主机决定开始、检查点激活、目标完成和结算。
- 客户端不得自行随机资源、路线或任务条件。
- 迟加入是否允许由 MVP 会话规则决定；若允许，必须获得当前关卡快照。
- 玩家离开不清除已完成目标。
- 主机退出时 MVP 可终止本局，不要求迁移。
- 测试日志记录默认变体、人数、阵容和完成时间。

## MVP范围

- 一个 LevelDefinition：《沉睡森林》。
- 一个独立关卡场景。
- 2～4 人。
- 四个初始角色允许重复选择。
- 三个主线机关与最终目标。
- 出生点、检查点、恢复点和关键物品恢复点。
- 10～20 分钟计时。
- 关卡变体数据边界；MVP 仅使用固定默认变体。
- 完成、结算和返回流程。
- 数据校验与开发调试信息。

## 非MVP范围

- 连续开放大世界。
- 多场景无缝流式加载。
- 多关卡剧情保存。
- 玩家关卡编辑器和发布。
- 自动生成完整地图。
- 复杂动态难度。
- 专用服务器关卡调度。
- 主机迁移。

## 验收标准

- 2、3、4 人可从加载完整走到结算。
- 大多数局为 10～20 分钟。
- 全队不开麦可完成。
- 缺少任一特定角色的代表阵容可通关。
- 四角色可重复选择的 65 个无序 2～4 人组合均通过结构通路校验；真实游玩覆盖最不利代表矩阵。
- 三个机关完成后只触发一次关卡完成。
- 普通失败只触发状态、救援或局部恢复。
- 固定默认变体在所有客户端一致。
- 默认变体不破坏通关、资源预算或目标时长。
- 关卡卸载后不残留机关、状态、标记和物品实例。
- Level 不包含三个机关的具体业务逻辑。

## 风险与待确认事项

### 风险

- 关卡编排职责膨胀为巨型管理器。
- 变体增加测试组合并破坏时长。
- 全队脱困与机关重置顺序冲突。
- 场景引用和数据 ID 不一致。
- 角色替代路径只在理论上可通关。

### 待确认

- MVP 是否允许中途加入。
- 结算后保留房间还是返回主菜单。
- MVP 后续首个变体选择资源点、支线路线还是任务条件。
- 《沉睡森林》的检查点数量和位置。
- 关卡超时是否只记录，不强制结束；当前建议不强制结束。
