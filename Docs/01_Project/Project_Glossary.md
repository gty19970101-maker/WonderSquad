# Wonder Squad 项目术语表

## 使用规则

- 中文文档优先使用“正式中文名”。
- 代码、数据 ID 和接口使用“代码名”。
- 未列出的同义词不得作为新的系统名或状态名。
- “依赖”仅指编译时引用；事件订阅、端口调用和数据消费应分别注明。

## 核心术语

| 正式中文名 | 代码名 | 定义 | 避免混用 |
|---|---|---|---|
| 主机 | Host / StateAuthority | MVP 中运行共享权威模拟的玩家客户端 | 服务器、权威端 |
| 客户端 | Client / InputAuthority | 提交本地输入并消费权威结果的非主机实例 | 权威客户端 |
| 机关 | Puzzle | 一组可交互、可同步、可重置并具有完成条件的环境挑战 | 谜题系统、机关系统混作实例名 |
| 机关定义 | PuzzleDefinition | 单个机关的静态数据定义 | Puzzle 脚本 |
| 解法路径 | SolutionPath | 使机关目标完成的一组声明条件和动作 | 方案、路线（未标明上下文） |
| 角色能力 | Ability | 角色对移动、制作、环境或信息的特定操作方式 | 技能（容易暗示战斗或成长） |
| 能力标签 | AbilityTag | 环境与机关查询能力类别的稳定标识 | 角色类名检查 |
| 物品 | Item | 所有可定义物品的总称 | 道具作为总类 |
| 资源 | Resource | 以团队库存数量表示的物品分类 | 场景道具 |
| 工具 | Tool | 制作后以场景实例使用的功能物品 | 资源 |
| 机关部件 | PuzzlePart | 放入机关插槽的场景实例 | 抽象库存材料 |
| 关键物品 | QuestItem | 丢失会阻断主线、必须具有恢复规则的物品 | 普通道具 |
| 临时状态 | Status | 由主机确认、具有持续与解除规则的运行时效果 | 搞笑状态、失败状态、状态效果 |
| 失败事件 | FailureEvent | 触发临时状态、位置变化或局部恢复的事件 | 死亡 |
| 救援 | Rescue | 队友解除另一玩家临时状态的权威交互 | 复活 |
| 检查点 | Checkpoint | 玩家进行位置恢复时使用的权威位置 | 物品恢复点 |
| 恢复点 | RecoveryPoint | 关键物品或系统对象恢复时使用的位置 | 玩家检查点 |
| 恢复事务 | RecoveryTransaction | 跨玩家、物品、机关和状态的有序恢复流程 | 各模块独立重置 |
| 关卡变体 | LevelVariant | 固定关卡内资源、路线或条件的白名单组合 | 随机地图、有限随机 |
| 场景标记 | Marker | 玩家发送的世界与小地图语义标记 | Ping、快捷消息 |
| 快捷意图 | QuickIntent | 来这里、等待、需要帮助等离散语义消息 | 表情 |
| 角色动作 | Emote | 指向、挥手、庆祝等短暂表现 | 快捷意图 |
| 静态定义 | ContentDefinition | 随构建提供、带稳定 ID 和版本的只读内容 | 运行时状态 |
| 权威运行时状态 | AuthoritativeState | 主机持有并同步的当前会话状态 | 本地存档 |
| 本地表现状态 | PresentationState | 摄像机、UI、动画等不影响玩法结果的状态 | 权威状态 |

## 依赖术语

| 术语 | 定义 |
|---|---|
| 编译时依赖 | 一个程序集直接引用另一个程序集的类型 |
| 查询端口 | 只读接口，不允许修改被查询领域 |
| 命令端口 | 请求另一领域执行由其拥有的规则 |
| 领域事件 | 某领域已经发生事实的不可变通知 |
| 消费者 | 订阅事件或读取 ViewModel 的模块，不代表被消费模块反向依赖 |

## MVP 范围术语

- **P0 双人无麦窄切片：** 最小可验证玩法链。
- **P1 完整 MVP：** 2～4 人、四个角色、三个机关和完整《沉睡森林》。
- **P2 MVP 后续：** 语音 SDK、实际关卡变体和更多能力。
