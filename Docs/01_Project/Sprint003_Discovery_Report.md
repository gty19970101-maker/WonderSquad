# Sprint003 — First Gameplay Vertical Slice Discovery Report

## 1. 结论

当前稳定基线为 `v0.7-interaction-foundation`：Unity `6000.3.21f1`、EditMode `74/74`、PlayMode `47/47`、Console Error `0`。

**推荐 Sprint003 正式方向：森林信标试炼（暂定体验名）——一个 3～5 分钟的本地环境解谜窄切片。**

它应验证的最小闭环是：

```text
看见目标与环境线索
→ 观察并形成假设
→ 选择通用路线或角色优势路线
→ 通过既有 Interaction 请求改变有限环境状态
→ 看见可读的路径结果
→ 错误时经历欢乐但可继续的局部后果
→ 到达目标区域
```

这不是完整《沉睡森林》、不是通用 Puzzle Framework，也不预先决定 Door、Lever、Pressure Plate 或具体机关类别。它是验证“观察、选择、环境后果与恢复”是否有趣的本地玩法门槛。

**重要边界：单机切片不能证明多人合作是否好玩。** 它只能在接入网络前降低玩法、内容与可读性风险。只有后续双人、全程不开麦的实际游玩，才能验证合作、救援和非语音沟通的核心承诺。

## 3. 当前最小可玩闭环

### 3.1 下一步应当验证什么

下一步不是“再做一种可交互物”，而是让玩家能够理解**一个可观察的环境问题**，做出有取舍的行动，并看到可预测但有趣的结果。

当前最小闭环的优先级为：

1. **观察与理解**：玩家从环境、图标、形状、空间关系中读到目标与线索。
2. **环境交互与选择**：玩家不是只按一次交互键，而是在两条可读路径中选择一种推进方式。
3. **角色能力差异的方向**：至少一个 AbilityTag 以后可令某条路径更快、更安全或信息更充分；通用路径始终存在。
4. **欢乐失败与恢复**：错误尝试只造成短暂、可理解、可返回的局部后果，不重开场景。
5. **完成反馈**：玩家明确知道“我的选择改变了环境，并让我抵达了目标”。

多人真实分工、多人同步窗口、共享资源、道具、制作和完整救援都不是该本地闭环的前置条件；它们应建立在这条环境因果链已被证明可读、有选择、值得协作之上。

### 3.2 本地切片的验证重点

Sprint003 首先验证：**观察驱动的环境解谜与自选解决方案。**

它只对以下核心乐趣给出早期证据：

| 核心乐趣 | Sprint003 本地切片验证强度 | 说明 |
| --- | --- | --- |
| 观察 | 强 | 环境必须提供可读线索，而不是依赖文字说明或试错穷举。 |
| 策略/选择 | 中强 | 通用路线与优势路线有明确时间、风险或信息差。 |
| 环境交互 | 强 | 交互必须导致可见、有限、可恢复的环境状态变化。 |
| 解谜 | 中强 | 玩家应根据线索选择顺序或路径，而不是连续点击。 |
| 角色能力差异 | 中 | 在数据和内容设计中预留一个实际优势位；完整能力验证放入后续子 Sprint。 |
| 合作 | 弱（仅为未来留边界） | 单机不能证明协作；不把代理、假队友或双控伪装成合作测试。 |
| 非语音交流 | 弱（仅验证语义可读） | 可验证提示与 Marker 的语义设计，但必须等双人无麦测试才算通过。 |

## 4. 是否现在实现 Door、Switch 或 Pressure Plate

**不应以“Interaction Framework 已完成”为理由，直接进入 Door、Switch 或 Pressure Plate。**

这些只是可能的表现或内容物，并不是当前要验证的玩法问题。现在直接实现它们，容易得到“按键后物体变化”的技术演示，却没有证明玩家是否观察、选择、协作或从失败中继续。

Sprint003 应先锁定下列**行为需求**，再在 Preflight 中选择最小的内容对象组合：

- 两个可从环境读到含义的交互点或状态点。
- 一个有限的、可观察的环境状态变化；例如路线显现、阻挡缩退、踏脚点形成或信号被校准。
- 一条所有合法角色均可使用的通用路径。
- 一个可选的角色优势入口，且只缩短、降低风险或揭示信息，绝不成为唯一条件。
- 一次局部、欢乐、可恢复的错误后果。
- 一个目标区域或明确完成触发。

如 Preflight 证明“状态点 + 路线表现”的最小组合可满足上述需求，就使用它；如果需要特定 Door 或 Pressure Plate，必须说明其只承担本切片的内容职责，而不是被抽象成新的通用 Framework。

## 5. 推荐微型关卡：森林信标试炼

### 5.1 目标与时长

- **目标时长**：3～5 分钟。
- **场景形态**：独立灰盒微型区域，可位于专用 Vertical Slice Sandbox；不修改《沉睡森林》正式关卡资产。
- **玩家目标**：唤醒两处森林信标，使通往终点树台的安全路线出现，并进入终点区域。
- **核心问题**：玩家需要先观察符号、视线与环境关系，再选择通过哪条路线校准第二处信标。

### 5.2 玩家体验流程

```text
出生区：可远望终点树台与两处信标
↓ 约 20–30 秒
教学线索区：读懂“相同符号 / 正确顺序 / 路线结果”的纯视觉语言
↓ 约 30–45 秒
选择区：
  通用长路线（所有角色可达）
  或未来角色优势入口（更短、更安全或信息更直接）
↓ 约 60–90 秒
校准区：与两个信标完成有限顺序的 Interaction
↓ 约 30–60 秒
结果：正确则显现安全路线；错误则进入安全的滑稽支线并可回到主线
↓ 约 30–60 秒
终点树台：进入完成区域，展示完成反馈
```

### 5.3 玩家进入后应看到、理解和做什么

| 时刻 | 玩家看到 | 应理解 | 应做 |
| --- | --- | --- | --- |
| 出生 | 高处终点、两处远方信标、被阻断但可见的路线 | “我的目标在前方；环境可被改变。” | 朝线索区移动。 |
| 线索区 | 重复的图形、方向性植物/灯光、局部示范状态 | “两个信标有可观察的关系或顺序。” | 观察、试探或使用未来的 Marker 表达发现。 |
| 选择区 | 更长的公共绕行路与一条能力优势入口 | “不一定只有一条办法；优势路线不是强制。” | 选路线抵达第二信标。 |
| 校准区 | 既有 Prompt 与强可见的本地反馈 | “交互成功不是终点，状态变化必须影响环境。” | 按线索完成两次有限交互。 |
| 错误 | 弹到安全叶垫/被藤蔓短暂拖入支线，主路仍在 | “我没有死，也不必重开；能看出如何回来。” | 返回、修正顺序或改走通用路线。 |
| 完成 | 安全路线出现、终点清晰可达 | “我们/我已经解决了环境问题。” | 进入终点并获得明确完成反馈。 |

### 5.4 失败与恢复的最低规则

错误交互不得清空整个切片、销毁关键状态或重载场景。最小失败输出应满足：

- 后果在数秒内可理解，且不依赖语音或音效。
- 玩家被送到安全支线、短暂受阻或失去最优路线，而不是被软锁。
- 回到主线的方式始终可见；首次失败后应在约 30 秒内恢复到可继续状态。
- 正确结果与错误结果必须在环境上可区分，不能只靠颜色。
- 后续双人版可把同一失败点扩展为 `Status` 与 `Rescue`，但 Sprint003 不应先做通用 Status/Rescue Framework。

## 6. 多解法、角色与人数扩展边界

### 6.1 解决方案结构

| 路径 | 当前/未来条件 | 价值 | 通关保证 |
| --- | --- | --- | --- |
| 通用路径 | 环境线索 + 公共绕行路 + 两次合法交互 | 所有玩家可理解、可独立完成的基准解 | 必须始终存在。 |
| 观察优势路径 | 未来 `AbilityTag` 揭示第二信标或正确顺序 | 减少观察成本与错误风险 | 只提供信息优势，不替代通用线索。 |
| 探险优势路径 | 未来 `AbilityTag` 进入预定义高处/短路 | 缩短路程或更安全抵达 | 公共路线仍可到达同一状态点。 |
| 后续协作路径 | 两人分别确认线索和操作状态，或在可读时间窗内完成 | 减少等待、增加分工 | 永远不能要求超过两人。 |

工匠与魔法师的优势入口可在后续完整《沉睡森林》中基于预定义 Socket/EnvironmentState 接入；Sprint003 不应为了“覆盖四个角色”提前引入资源、制作或复杂环境变形。

### 6.2 2 人、3～4 人与未来更大队伍

正式 MVP 设计与网络目标是 **2～4 人**。本切片必须从数据和流程上避免硬编码“Player 1/Player 2”或强制四人，但不实施 5～10 人运行支持。

- **2 人**：一人观察/标记，一人前往信标；任何同步要求都只以两人为基础。
- **3～4 人**：允许并行观察、路线探索或容错，不增加必须参与人数。
- **5～10 人（非 MVP 研究方向）**：只能通过多个可选贡献位、分区探索或旁观信息贡献扩展；不得把一个机关的必需参与人数直接扩大到 5～10。真正支持该规模还需要网络、关卡密度、镜头、交流限流和性能的独立产品决策，不应由 Sprint003 预先承诺。

### 6.3 非语音交流的未来接入

线索、信标状态、可达路线、错误结果和“下一步该做什么”必须具备纯视觉语义。未来接入 `Marker` 与 `QuickIntent` 时，玩家应能用“来这里”“我来操作”“等等”“需要帮助”表达计划；该语义接入现有 Communication 边界，不能让关卡逻辑读取语音内容或本地化字符串。

## 7. 当前真正阻塞 Vertical Slice 的最小系统

以下是完成推荐本地切片的必要缺口。它们是内容级或窄领域能力，不应合并为新通用 Framework。

| 阻塞项 | 为什么必要 | 最小边界 |
| --- | --- | --- |
| 有限环境状态与目标完成 | 需要把已存在的交互请求变成可观察、可恢复的玩法结果 | 仅服务森林信标试炼的有限状态、完成条件与局部复位；不创建通用 Puzzle State Framework。 |
| 角色能力最小端口与一个优势路径 | 没有能力入口就不能验证“角色差异改变过程” | 使用 AbilityTag 与预定义目标/锚点；先实现一个代表性能力方向或只完成内容接缝验证，不能自由建造、自由绳索或复杂物理。 |
| 失败后果与本地恢复 | 需要验证“不重开也能继续”的基本感受 | 一个可读的安全支线/短暂状态和返回路径；不建立完整 Status/Rescue 系统。 |
| 目标/完成表现 | 玩家需要知道何时成功、为什么成功 | 单个本地目标状态与终点触发；不建立完整 Level 生命周期或结算系统。 |
| 最小内容数据与校验 | 需要稳定 ID、明确状态、通用路径与优势路径声明 | 仅本切片的白名单数据和合法性检查；不建立玩家编辑器、随机变体或复杂内容浏览。 |

`Marker`/`QuickIntent` 是后续双人无麦验证的阻塞项，但不是先让单机环境因果链跑通的阻塞项。若 Sprint003 的定义要求立刻宣称“无麦合作已验证”，则它们和实际双人网络都变为阻塞项；本报告不作该不诚实声明。

## 8. 当前明确不应实现的系统

- Photon Fusion、房间、玩家同步、Network Authority 运行时代码或多人重连。
- Inventory、资源采集、携带物、制作、配方、世界物理道具和关键物品恢复。
- Door、Lever、Pressure Plate 的通用族谱或“所有机关都能用”的抽象层。
- 通用 Puzzle Framework、通用状态机、EventBus、Service Locator 或全局 Gameplay Manager。
- 完整 Status/Rescue、能力树、四角色全量能力、跳跃/攀爬扩展、战斗或 AI。
- 完整 Level 流程、关卡变体、Save、后端、语音 SDK、玩家编辑器。
- 任何对 Sprint001/Sprint002 已通过 Gate 的基础架构修改。

## 10. 推荐的 Sprint003 子 Sprint

这些子 Sprint 是实施顺序建议，不构成当前授权实现。

### Sprint003A — Environmental Cause-and-Effect Preflight

- 锁定森林信标试炼的目标、视觉语言、通用路径、可恢复错误后果和完成条件。
- 决定最小内容对象组合，但不把它们提升为 Door/Switch/Puzzle 通用类。
- 产出：对象职责、有限状态表、内容数据草案、依赖图、测试和人工验收计划。
- Gate：所有状态可观察、通用路径存在、任何状态无单机软锁。

### Sprint003B — Local Environmental Core

- 在独立灰盒场景建立两处状态点、有限环境变化、通用路线与本地目标完成。
- 复用 Interaction 的 Detection → Prompt → Execution；具体对象通过组件组合接入。
- Gate：从出生到完成可在 3～5 分钟内跑通；交互和环境变化不改变 Character Foundation 或 Interaction Foundation。

### Sprint003C — Advantage Route and Recoverable Failure

- 接入一个预定义 AbilityTag 优势入口，且保留同一结果的通用路径。
- 加入一次可读、搞笑、局部且可在约 30 秒内恢复的失败后果。
- Gate：优势路径不形成硬锁；失败不重载场景、不吞掉关键状态；两条路径汇聚到同一完成状态。

### Sprint003D — Readability and Vertical Slice Gate

- 完善无需语音即可读懂的环境提示，定义后续 Marker/QuickIntent 接入点与体验埋点。
- 以陌生测试者进行单机盲测：理解目标、首次理解时间、错误恢复时间、是否主动尝试替代路径。
- Gate：决定是否进入双人无麦窄切片的 Network/Communication 预检；不在本 Sprint 直接写网络代码。

## 11. Sprint003 的完成定义与后续决策

Sprint003 完成并不等于 MVP 完成，也不等于“多人合作已验证”。它应能明确回答：

1. 玩家能否通过纯环境信息理解一个小目标？
2. 玩家是否认为自己的选择改变了环境，而非只是在按按钮？
3. 通用路径和角色优势路径是否都可理解，且优势不构成硬锁？
4. 失败是否带来笑点和新的短暂情境，而不是挫败或重开？
5. 这条因果链是否值得投入真正的双人无麦、资源/道具与后续机关开发？

若任一问题为否，应先调整内容语言、路径或失败后果，而不是用网络、库存或更复杂机关掩盖问题。若通过，下一次发现阶段应针对“双人无麦窄切片”单独进行 Network、Communication、Ability 与 Status/Rescue 的范围预检。
