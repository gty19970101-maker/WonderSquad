# Wonder Squad 第一版可玩原型任务分解

## 0. 文档目的

本文把第一版可玩原型拆成可按依赖顺序逐项实现、独立验证和回归测试的任务。执行顺序固定为：

```text
P0 项目初始化
→ P1 单人基础操作
→ P2 物品闭环
→ P3 机关闭环
→ P4 角色能力
→ P5 欢乐失败
→ P6 非语音交流
→ 单机核心闭环评审
→ P7 联机
→ P8 完整《沉睡森林》
```

P0～P6 先在离线单机模式完成领域规则和表现闭环；P7 再通过 Photon Fusion 2 Host Mode 接入 2～4 人联机。网络层只能转发意图和复制权威结果，不重新实现一套玩法规则。

> 注意：本文的 P0～P8 是“原型开发里程碑”，与项目术语表中的“产品 P0 双人窄切片 / 产品 P1 完整 MVP / 产品 P2 后续功能”不是同一套编号。本文 P6 完成后对应单机原型门槛；P7 前半对应产品 P0；P8 完成对应产品 P1。

当前只定义任务，不创建任何 Unity 业务代码、场景或资源。

---

## 1. 执行标记

### 1.1 MVP阻塞标记

- **是：** 未完成会导致完整 MVP 无法运行、无法通关或无法验证核心体验。
- **否：** 可以延期而不阻断第一版闭环，但仍可能属于测试、维护或质量改进。

### 1.2 占位资源标记

- **临时模型允许：** 可使用胶囊体、立方体、基础材质和简单粒子。
- **占位UI允许：** 可使用纯文本、色块、默认图标和调试面板。
- **占位音效允许：** 可使用无版权测试音或短提示音，也可在早期静音验证。
- 占位资源不能成为机关唯一信息来源；重要信息始终需要形状、文字或状态反馈。

### 1.3 计划路径约定

Unity 客户端根目录按 `Client/` 规划，业务资源统一放入：

```text
Client/Assets/WonderSquad/
```

以下任务中的“创建或修改文件”均为后续执行计划，不表示本文生成了这些文件。

## 2. 总体依赖与阶段出口

| 里程碑 | 主要输出 | 阶段出口 |
|---|---|---|
| P0 | 可打开、可运行、边界清晰的 Unity 项目 | 测试场景可运行，输入与程序集可用 |
| P1 | 单人移动和统一交互 | 可移动、观察目标并收到提示 |
| P2 | 木材进入共享库存并原子消耗 | 完成资源最小闭环 |
| P3 | 按钮、门、破损桥、修复和终点 | 单人可完成最小关卡闭环 |
| P4 | 四角色各一个数据驱动能力 | 能力有优势但无角色硬锁 |
| P5 | 状态、救援、超时恢复和笑点 | 失败后可继续，不重开场景 |
| P6 | 标记、快捷意图和表情 | 不依赖语音可表达计划与求助 |
| P7 | 2～4 人 Host Mode 联机 | 共享结果全部由主机确认 |
| P8 | 完整《沉睡森林》 | 2～4 人、约 15 分钟、无麦可通关 |

单机核心闭环评审是 P7 的强制进入条件：

- 一名玩家能从出生走到终点。
- 能拾取木材、看到数量、消耗资源并修复桥。
- 能使用至少两种角色能力完成不同方案。
- 能触发状态并通过代理救援或超时恢复。
- 能发送地面标记、快捷意图和表情。
- 上述过程不依赖网络 SDK。

# P0：项目初始化

## P0-001　锁定Unity项目配置与包版本

- **MVP阻塞：** 是
- **目标：** 用项目唯一正式版本 Unity `6000.3.21f1`（Unity 6.3 LTS）创建 Universal 3D/URP 客户端项目，并锁定 Input System、测试框架和基础包版本；暂不接入 Fusion 与语音 SDK。
- **输入条件：** v1.1 技术架构；本机已安装目标 Unity Editor。
- **需要创建或修改的文件：** `Client/Packages/manifest.json`、`Client/Packages/packages-lock.json`、`Client/ProjectSettings/ProjectVersion.txt`、`Client/ProjectSettings/GraphicsSettings.asset`、`Client/ProjectSettings/QualitySettings.asset`、`Client/README.md`。
- **Unity场景配置：** 暂不创建业务场景；确认默认 URP Renderer 和测试用质量档位。
- **占位资源：** 临时模型、占位UI、占位音效均允许。
- **验收步骤：** 1）用锁定版本打开项目；2）等待无错误导入；3）进入空场景运行；4）执行一次本地开发构建；5）重新打开确认包版本不漂移。
- **完成标准：** 编辑器和开发构建均无阻塞错误；版本和目标平台写入 README；未安装语音 SDK。
- **依赖任务：** 无。
- **常见风险：** 使用非 LTS 版本；URP 资源缺失；不同成员自动升级包；过早加入第三方包。

## P0-002　建立目录与程序集边界

- **MVP阻塞：** 是
- **目标：** 建立 `Core/Contracts`、Content、Player、Ability、Interaction、Communication、Inventory、Item、Crafting、Puzzle、Status、Level、Network、UI 和 Save 的目录与 Assembly Definition 边界。
- **输入条件：** P0-001；技术架构的依赖矩阵。
- **需要创建或修改的文件：** `Client/Assets/WonderSquad/` 下规划目录；各模块 `.asmdef`；`Client/Assets/WonderSquad/Tests/` 下 EditMode、PlayMode、Network、ContentValidation 测试程序集。
- **Unity场景配置：** 无业务对象；项目能在空场景加载全部程序集。
- **占位资源：** 不涉及模型、UI或音效。
- **验收步骤：** 1）触发完整编译；2）检查各程序集引用；3）确认 Gameplay 领域只通过 Core/Contracts 和 Content 协作；4）运行空测试程序集。
- **完成标准：** 无循环程序集依赖；Fusion 类型尚未进入领域程序集；不存在无边界 `Managers` 或 `Misc` 目录。
- **依赖任务：** P0-001。
- **常见风险：** 模块拆得过细；UI 被领域模块反向引用；Content 持有运行时状态；先建立“万能管理器”。

## P0-003　建立稳定ID、内容定义和校验骨架

- **MVP阻塞：** 是
- **目标：** 规划稳定 ID、内容版本、只读 ContentDefinition 和最小结构校验入口，只覆盖当前原型会使用的定义类型。
- **输入条件：** P0-002；Data Driven Design；项目术语表。
- **需要创建或修改的文件：** 计划创建 `Scripts/Core/Identifiers/`、`Scripts/Content/Definitions/`、`Scripts/Content/Validation/`；测试放入 `Tests/ContentValidation/`；首个测试资产放入 `Content/Levels/Tests/`。
- **Unity场景配置：** 在测试场景根对象上放置内容目录引用；不创建玩家编辑器。
- **占位资源：** 不涉及模型和音效；错误提示可用占位UI。
- **验收步骤：** 1）加载一个带稳定 ID 和版本的测试定义；2）制造重复 ID；3）制造缺失引用；4）确认校验器给出定位明确的错误；5）恢复合法配置。
- **完成标准：** 合法定义可加载；重复 ID、空 ID、缺失引用可检测；校验器不声称证明物理可通关。
- **依赖任务：** P0-002。
- **常见风险：** 把数据模型扩展成脚本语言；为未来编辑器提前做复杂序列化；校验职责超过结构检查。

## P0-004　配置Unity输入系统

- **MVP阻塞：** 是
- **目标：** 建立移动、观察、跳跃、交互、能力、标记、快捷轮盘、表情、救援和暂停输入图，支持键鼠与手柄。
- **输入条件：** P0-001、P0-002；现有 Player、Interaction、Communication 设计。
- **需要创建或修改的文件：** `Client/Assets/WonderSquad/Settings/Input/WonderSquad.inputactions`、输入设置资产、计划中的输入适配器文件和输入测试。
- **Unity场景配置：** 在输入测试场景添加一个 PlayerInput 测试对象和屏幕输入调试面板。
- **占位资源：** 占位UI允许；不需要模型和音效。
- **验收步骤：** 1）逐项触发所有 Action；2）切换键鼠和手柄；3）验证交互、标记和能力不是同一冲突绑定；4）暂停后恢复输入；5）断开手柄并重新连接。
- **完成标准：** 所有 MVP Action 都有稳定语义名和至少一套可用绑定；输入层不直接执行玩法结果。
- **依赖任务：** P0-001、P0-002。
- **常见风险：** 轮盘与摄像机输入冲突；手柄缺少可达按键；把输入回调直接绑定到场景业务对象。

## P0-005　建立测试场景与基础验证入口

- **MVP阻塞：** 是
- **目标：** 建立 Bootstrap、单人专项测试场景和最小 PlayMode 验证入口，使后续任务都能在隔离场景中测试。
- **输入条件：** P0-002、P0-003、P0-004。
- **需要创建或修改的文件：** `Scenes/Bootstrap/Bootstrap.unity`、`Scenes/Tests/PlayerSandbox.unity`、`Scenes/Tests/GameplaySandbox.unity`、`Scenes/Tests/RecoverySandbox.unity`、Build Profiles/场景列表、基础测试清单。
- **Unity场景配置：** 每个 Sandbox 只保留地面、灯光、摄像机挂点、出生点、边界和调试画布；Bootstrap 可选择加载测试场景。
- **占位资源：** 临时模型、占位UI和占位音效均允许。
- **验收步骤：** 1）从 Bootstrap 分别进入三个 Sandbox；2）重复加载和卸载；3）确认无对象残留；4）从开发构建进入指定测试场景。
- **完成标准：** 后续单项功能无需打开《沉睡森林》即可验证；测试场景不引用未来完整关卡专属逻辑。
- **依赖任务：** P0-002、P0-003、P0-004。
- **常见风险：** 所有测试堆进一个场景；测试场景依赖编辑器专用对象；Bootstrap 过早变成巨型服务定位器。

### P0阶段出口

- Unity版本、URP、目标平台和包版本已锁定。
- 程序集依赖无环。
- 输入图和三个 Sandbox 可用。
- 至少一个数据定义通过结构校验。

# P1：单人基础操作

## P1-001　建立离线玩家Prefab与状态边界

- **MVP阻塞：** 是
- **目标：** 建立可在离线 Sandbox 生成的玩家 Prefab、PlayerId、角色状态和表现分层，为后续网络替换生成方式预留边界。
- **输入条件：** P0-005。
- **需要创建或修改的文件：** 计划创建 `Scripts/Player/`、`Prefabs/Player/PF_Player_Prototype.prefab`、PlayerDefinition 测试资产和 PlayMode 测试。
- **Unity场景配置：** PlayerSandbox 放置一个离线出生点，由测试启动器生成一名玩家。
- **占位资源：** 临时胶囊模型允许；占位UI允许；音效可省略。
- **验收步骤：** 1）进入场景生成一次；2）重载场景确认不重复生成；3）切换角色测试定义；4）检查状态与表现对象可分别启停。
- **完成标准：** 玩家有稳定身份、输入入口和只读状态输出；玩法代码不依赖具体模型骨骼。
- **依赖任务：** P0-005。
- **常见风险：** 玩家 Prefab 承担所有系统职责；离线生成逻辑无法被网络生成替换；角色外观与能力逻辑耦合。

## P1-002　实现基础移动与跳跃

- **MVP阻塞：** 是
- **目标：** 完成移动、转向、跳跃、落地和越界检测的离线手感闭环。
- **输入条件：** P1-001、P0-004。
- **需要创建或修改的文件：** 计划修改 Player 移动相关文件、Physics 设置、玩家 Prefab 和 Player PlayMode 测试。
- **Unity场景配置：** PlayerSandbox 配置平地、斜坡、低台、窄桥、落差和 OutOfBounds Volume。
- **占位资源：** 临时模型允许；占位UI允许；脚步和跳跃占位音效允许。
- **验收步骤：** 1）键鼠和手柄各移动 2 分钟；2）通过斜坡和低台；3）连续跳跃；4）掉出边界；5）验证回到测试出生点且控制恢复。
- **完成标准：** 无明显穿地、永久悬空或输入锁死；移动参数集中配置；越界不重载场景。
- **依赖任务：** P1-001。
- **常见风险：** 依赖帧率；角色控制器与动态刚体混用；2.5D 摄像方向和移动方向不一致。

## P1-003　实现受控2.5D摄像机

- **MVP阻塞：** 是
- **目标：** 建立跟随、旋转限制、距离、遮挡处理和恢复规则，保证机关与交互目标清晰。
- **输入条件：** P1-002。
- **需要创建或修改的文件：** 摄像机控制与配置资产、`Prefabs/Player/PF_PlayerCameraRig.prefab`、摄像机 PlayMode 测试。
- **Unity场景配置：** PlayerSandbox 增加遮挡墙、高低差、树冠和狭窄门洞测试段。
- **占位资源：** 临时模型允许；占位UI允许；音效不需要。
- **验收步骤：** 1）绕场景移动；2）穿过门洞和遮挡区；3）快速转向；4）跌落恢复；5）验证摄像机不留在旧位置。
- **完成标准：** 玩家始终可定位；重要交互目标不长期被遮挡；摄像机状态仅本地处理。
- **依赖任务：** P1-002。
- **常见风险：** 自动旋转引发眩晕；遮挡淡化成本过高；摄像机状态错误进入网络权威。

## P1-004　实现统一交互检测

- **MVP阻塞：** 是
- **目标：** 实现目标发现、距离/方向/遮挡查询、候选排序和标准 InteractionCommand，不直接在检测层改变目标状态。
- **输入条件：** P1-002、P1-003、P0-002。
- **需要创建或修改的文件：** 计划创建 `Scripts/Interaction/`、Core/Contracts 中交互命令与查询契约、`Prefabs/Interaction/PF_Interactable_Test.prefab` 和测试。
- **Unity场景配置：** GameplaySandbox 放置近距、远距、遮挡、重叠和不可用五类交互目标。
- **占位资源：** 临时模型和占位UI允许；占位音效允许。
- **验收步骤：** 1）靠近单一目标；2）同时面对两个目标；3）隔墙尝试；4）离开范围；5）快速重复输入；6）检查只发出标准命令。
- **完成标准：** 目标选择稳定；越距和遮挡目标不可执行；交互检测不直接依赖按钮、门或资源的具体类。
- **依赖任务：** P1-002、P1-003。
- **常见风险：** 每帧扫描过多对象；交互候选闪烁；把本地“可用提示”误当成权威成功。

## P1-005　实现可交互提示

- **MVP阻塞：** 是
- **目标：** 根据只读交互状态显示目标名称、输入键、交互类型和不可用原因。
- **输入条件：** P1-004。
- **需要创建或修改的文件：** 计划创建 UI 交互提示 ViewModel、`Prefabs/UI/PF_InteractionPrompt.prefab`、本地化键和 UI 测试。
- **Unity场景配置：** GameplaySandbox 添加 Screen Space 提示画布与世界目标高亮。
- **占位资源：** 占位UI必须允许；临时模型和占位音效允许。
- **验收步骤：** 1）对五类测试目标逐一观察提示；2）切换键鼠/手柄；3）资源不足时显示原因；4）移开视线确认提示消失。
- **完成标准：** 提示与实际可执行状态一致；不会因提示隐藏改变玩法；重要信息不只用颜色表达。
- **依赖任务：** P1-004。
- **常见风险：** UI轮询领域内部状态；提示频繁闪烁；不可用原因与真正拒绝原因不一致。

### P1阶段出口

- 单人可以稳定移动、跳跃和观察环境。
- 可交互目标能被统一检测并显示正确提示。
- 摄像机和 UI 都保持本地表现职责。

# P2：物品闭环

## P2-001　定义木材资源与资源节点

- **MVP阻塞：** 是
- **目标：** 建立 `resource.wood` 的 ItemDefinition、固定资源节点状态和拾取交互入口。
- **输入条件：** P0-003、P1-004。
- **需要创建或修改的文件：** `Content/Items/Resource_Wood.asset`、计划中的 Item/Resource 定义文件、`Prefabs/Items/PF_ResourceNode_Wood.prefab` 和内容校验测试。
- **Unity场景配置：** GameplaySandbox 放置三个固定木材节点，分别测试可拾取、耗尽和禁用状态。
- **占位资源：** 临时木块模型、占位UI和占位音效均允许。
- **验收步骤：** 1）靠近节点；2）拾取；3）重复拾取；4）重载场景；5）检查稳定 ID、数量和耗尽状态。
- **完成标准：** 单个节点只产出一次配置数量；拾取后场景实例耗尽；重复请求不会重复产出。
- **依赖任务：** P0-003、P1-004。
- **常见风险：** 资源节点直接修改 UI；掉落实例与库存数量同时存在；ID 使用场景名称代替稳定 ID。

## P2-002　实现离线团队共享库存

- **MVP阻塞：** 是
- **目标：** 建立 TeamInventory 的离线单参与者实现、资源数量快照和 Revision；不要创建个人容量背包。
- **输入条件：** P2-001、P0-002。
- **需要创建或修改的文件：** 计划创建 `Scripts/Inventory/`、Core/Contracts 中库存命令/快照/端口、Inventory EditMode 测试。
- **Unity场景配置：** GameplaySandbox 注册一个离线 TeamInventory 服务，不在玩家 Prefab 内持有库存真相。
- **占位资源：** 占位UI允许；不需要模型和音效。
- **验收步骤：** 1）增加木材；2）查询数量；3）重复 RequestId；4）尝试负数和超界修改；5）重新开始测试局。
- **完成标准：** 数量唯一、非负、带 Revision；重复请求幂等；接口以后可由主机权威实现替换。

## 4. 推荐的小团队执行方式

### 个人开发

严格串行执行本文顺序。每个任务完成时至少保留：

- 一个可重复的验收场景。
- 一个成功路径测试。
- 一个拒绝、重复请求或恢复路径测试。
- 一条简短的结果记录。

### 2人团队

- 成员 A：当前里程碑的领域规则、命令、快照和测试。
- 成员 B：对应 Prefab、场景配置、UI反馈和人工验收。
- 两人不得同时在不同里程碑引入相互依赖的运行时系统。
- P7 时，一人负责 Fusion Adapter，一人负责领域回归和双实例测试。

### 3人团队

- 成员 A：领域规则与数据。
- 成员 B：场景、Prefab 与表现。
- 成员 C：测试、工具、网络专项和内容校验。
- 并行工作必须围绕同一当前里程碑，不能跳到 P8 美术整合而 P3 闭环尚未稳定。

## 5. 每阶段通用完成规则

任何任务只有同时满足以下条件才可标记完成：

1. 任务列出的验收步骤已实际执行。
2. 成功、拒绝、重复请求和恢复路径中适用项均通过。
3. 没有把临时调试对象带入正式运行程序集或完整关卡。
4. 没有新增跨领域直接实现依赖或循环程序集依赖。
5. 占位资源的使用已记录，且不影响信息可读性。
6. 没有开始商城、氪金、排行榜、公会、大世界、复杂基地、战斗 Boss、玩家编辑器、UGC、语音 SDK 或独立后端。
7. 新增共享状态已明确未来由主机决定，或明确标记为仅本地表现。
