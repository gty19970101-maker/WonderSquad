# Player System

## 系统目标

提供清晰、响应及时且适合 2.5D 合作解谜的玩家角色基础，包括移动、跳跃、角色身份、持有点、交互点、摄像机目标和临时状态修饰。

玩家系统只表达操作和角色状态，不直接决定共享玩法结果。

## 系统边界

负责：

- 本地输入采集。
- 移动、转向、跳跃与基础地形通过。
- 玩家 ID、角色 ID 和本地/远端身份。
- 交互检测参考点、物品持有点和救援点。
- 动画与表现所需的运动状态。
- 应用权威能力或临时状态产生的移动修饰。
- 跌落检测与请求恢复。

不负责：

- 角色能力的具体效果。
- 资源、库存、制作和机关判定。
- 通信标记的生命周期。
- 自行传送、复活或解除状态。
- 复杂战斗、生命值、装备和属性成长。

## 核心流程

### 本地移动

```text
读取输入
→ 生成当前网络 Tick 的输入意图
→ 本地预测移动
→ 主机模拟并生成权威结果
→ 客户端接收校正
→ 表现层插值与动画
```

### 角色生成

```text
房间确认角色选择
→ 主机分配 PlayerId 与出生点
→ 生成网络角色
→ 绑定本地输入/摄像机或远端表现
→ 应用角色能力定义
```

### 跌落恢复

```text
检测越界
→ 向主机提交恢复请求
→ 主机确认当前检查点
→ 清理不合法持有关系
→ 权威传送
→ 播放趣味反馈
```

## 主要状态

### 生命周期

- `Unspawned`
- `Spawning`
- `Active`
- `Recovering`
- `Disconnected`

### 运动状态

- `Idle`
- `Move`
- `Jump`
- `Airborne`
- `Landing`
- `Carrying`
- `Interacting`
- `Rescuing`

### 状态修饰

玩家可能同时持有由 `Status_And_Failure_System` 管理的修饰，例如：

- 移动变慢
- 转向笨拙
- 暂时无法跳跃
- 被困住
- 被击飞

Player 只消费最终修饰，不拥有状态持续时间和解除规则。

## 与其他系统的依赖

编译时依赖：

- `Core/Contracts`：PlayerId、RoleId、输入、MovementModifier 和 PlayerState。

通过端口或事件协作：

- 发布 PlayerState、PlayerSpawned、PlayerDisconnected 和 RecoveryRequested。
- 消费 Ability、Interaction、Communication 的输入命令，但不引用其实现。
- 消费 Status 发布的 MovementModifier。
- 由 Level 通过 `IPlayerRecoveryPort` 指定出生点和检查点。
- 由 Network Adapter 读取输入并复制权威状态。

Player 不直接依赖 Ability、Interaction、Item、Status、Level、Puzzle、Recipe 或网络 SDK 实现。

## 联机同步要求

- 本地客户端拥有输入权，不拥有最终位置权。
- 主机决定位置、速度、跳跃合法性、击飞和恢复位置。
- 同步角色 ID、移动状态、持有关系和必要动画参数。
- 不逐帧同步本地摄像机或纯表现动画。
- 临时状态只同步状态标识和权威时间，不同步每个表现参数。
- 玩家离开时，主机解除其关键物品和救援关系。

## MVP范围

- 地面移动、转向和跳跃。
- 受控 2.5D 摄像机目标。
- 角色选择结果应用。
- 交互点、持有点和救援点。
- 跌落与检查点恢复。
- 受临时状态修饰。
- 基础动画状态接口。
- 键鼠与手柄。

## 非MVP范围

- 战斗、生命值和伤害。
- 游泳、飞行、载具和复杂攀爬系统。
- 装备、等级、天赋和数值属性。
- 完整角色自定义。
- 复杂布娃娃网络同步。
- 主机迁移时的角色保持。

## 验收标准

- 本地移动和跳跃手感稳定，摄像机不会频繁丢失目标。
- 2～4 人常见延迟下移动可接受。
- 客户端不能自行确认越界恢复或权威传送。
- 持有物、交互和救援使用统一空间参考点。
- 临时状态能正确改变操作并在解除后完全恢复。
- 玩家断线不会留下永久占用的持有点或救援关系。
- Player 模块不包含具体机关、配方或角色硬编码。

## 风险与待确认事项

### 风险

- 网络物理和移动预测互相影响。
- 2.5D 摄像机在多人分散时可读性下降。
- 状态修饰叠加造成不可操作。
- 角色能力直接写入移动控制器，形成强耦合。

### 待确认

- 探险家的攀爬是完整攀爬还是指定交互点动作。
- 多人是否共享摄像机区域；当前架构默认每人独立客户端摄像机。
- 携带重物是否改变移动速度。
- 跳跃容错、土狼时间和输入缓冲的目标参数。
