# Interaction System

## 系统目标

提供统一、可预测、可扩展的玩家交互入口，使采集、拾取、放置、制作、机关、能力目标和队友救援使用同一套“发现、提示、请求、权威判定、反馈”流程。

## 系统边界

负责：

- 在玩家附近发现可交互目标。
- 按距离、方向、遮挡、优先级和当前状态筛选。
- 生成本地可用性提示。
- 提交即时、持续、多人同步和插槽放置交互请求。
- 处理交互开始、取消、完成和拒绝反馈。
- 提供统一的交互上下文。

不负责：

- 采集、制作、能力、机关和救援的具体结果。
- 自行修改库存、物品或状态。
- 决定关卡完成。
- 场景标记和语音。

## 核心流程

### 目标选择

```text
收集范围内候选
→ 过滤不可见/不可达/不可用对象
→ 按明确优先级排序
→ 选择主目标
→ 查询本地提示
→ UI 展示操作与原因
```

### 权威交互

```text
玩家按下交互
→ 创建 InteractionContext
→ 客户端发送请求
→ 主机重新校验距离、状态、权限和目标版本
→ 调用目标所属系统
→ 返回接受/拒绝
→ 同步结果并播放反馈
```

### 持续或多人交互

```text
开始请求
→ 主机登记参与槽位
→ 持续检查玩家与目标有效性
→ 满足人数/时间窗时完成
→ 任一条件失效时取消或衰减
```

## 主要状态

- `OutOfRange`
- `Available`
- `Focused`
- `Requested`
- `InProgress`
- `Completed`
- `Cancelled`
- `Rejected`
- `Cooldown`

目标状态与玩家交互状态分离；一个目标可同时为不同玩家提供不同可用性。

## 与其他系统的依赖

编译时依赖：

- `Core/Contracts`：InteractionContext、IInteractable、目标 ID 和请求结果。

通过端口或事件协作：

- 使用 `IPlayerQuery` 获取交互点。
- 目标所属领域实现 `IInteractable` 与对应命令端口。
- Interaction 只发布标准命令，不引用 Item、Crafting、Puzzle、Status 或 Communication 实现。
- Network Adapter 传输 InteractionContext 并在主机重新校验。

## 联机同步要求

- 本地目标高亮不需要同步。
- 共享交互开始、参与槽位、进度和完成由主机决定。
- 主机必须重新检查距离、状态、目标 ID 和请求者。
- 同一物体争用产生唯一结果。
- 持续交互使用网络时间，不依赖本地帧时间。
- 交互请求幂等；完成后的重复请求返回当前状态。
- 客户端离开时，主机释放其交互槽位。

## MVP范围

- 即时使用。
- 采集。
- 拾取与放下。
- 插槽放置。
- 制作点交互。
- 机关操作。
- 持续救援。
- 最小多人同步时间窗。
- 键鼠和手柄提示。

## 非MVP范围

- 复杂对话树。
- 战斗锁定和攻击目标。
- 任意拖拽编辑器操作。
- 大规模多人抢占和排队。
- 高精度手部 IK 交互。
- 玩家自定义交互脚本。

## 验收标准

- 所有 MVP 交互使用统一请求路径。
- 本地提示与主机结果不一致时能正确回退和说明。
- 两名玩家同时操作同一资源、道具或机关时结果唯一。
- 持续交互中断后无残留进度或占用。
- 目标排序稳定，不在相邻物体间快速跳动。
- 不同角色可获得不同提示，但不会因缺少角色隐藏通用解法。
- Interaction 不包含具体机关、配方或救援业务规则。

## 风险与待确认事项

### 风险

- 通用接口承担过多业务细节。
- 目标选择在密集场景中不稳定。
- 本地提示频繁被主机拒绝，产生迟滞感。
- 多人持续交互在高延迟下体验生硬。

### 待确认

- 默认交互范围和视角权重。
- 是否允许自动选择最近目标，还是需要方向输入。
- 多人同步机关允许的时间窗。
- 携带物体时交互键的放下、投掷和使用优先级。
