# Status and Failure System

## 系统目标

把普通失败转化为可继续游玩的搞笑状态、位置变化或队友救援机会，减少整关重开，制造合作笑点并保持节奏。

所有影响共享玩法的失败结果由主机确认。

## 系统边界

负责：

- StatusDefinition 与运行时实例。
- 状态施加、持续、叠加、修饰、解除和过期。
- 求救和队友救援流程。
- 检测并发布疑似全队无法互救事件；安全恢复由 Level Recovery Orchestrator 编排。
- 与机关局部重置、检查点和关键物品恢复协调。
- 状态反馈事件。

不负责：

- 玩家移动实现。
- 机关失败条件。
- 关键道具物理恢复。
- 完整死亡、生命值和复活系统。
- 长期负面效果或惩罚经济。

## 核心流程

### 状态施加

```text
机关或环境产生失败输入
→ 主机验证目标和当前状态
→ 创建 StatusInstance
→ 记录权威开始/结束时间
→ 同步状态
→ Player 应用控制修饰
→ UI/动画/Communication 显示
```

### 队友救援

```text
受困玩家进入可救援状态
→ 自动或主动发出求救
→ 队友接近并开始救援
→ 主机验证距离、状态与救援方式
→ 持续到完成或取消
→ 主机解除状态
→ 播放双方反馈
```

### 全队脱困

```text
主机检测所有有效玩家均无法行动且不存在可执行救援
→ 等待短暂安全窗口
→ 清理冲突状态和关键持有关系
→ 发布 PartyIncapacitated
→ Level Recovery Orchestrator 执行有序恢复
```

## 主要状态

### 状态实例

- `Pending`
- `Active`
- `BeingRescued`
- `Expired`
- `Cleared`

### MVP 效果方向

- 被弹飞
- 被藤蔓或泡泡困住
- 短时黏滑或笨拙
- 暂时无法执行特定动作
- 掉入安全支线区域

状态应短时、可理解、可解除，并有最终超时兜底。

## 与其他系统的依赖

编译时依赖：

- `Core/Contracts`：StatusCommand、RescueCommand、MovementModifier 和状态事件。
- `Content`：StatusDefinition 与救援配置。

通过端口或事件协作：

- 使用 `IPlayerQuery` 校验目标和救援者。
- 接收 Puzzle 或环境通过 `IStatusCommandPort` 发出的命令。
- 发布 StatusChanged、HelpRequested 和 PartyIncapacitated。
- Player、Communication、UI 与 Level 分别消费这些事件。
- 全队脱困由 Level Recovery Orchestrator 决定，Status 不依赖 Level。
- Network Adapter 复制状态快照。

## 联机同步要求

- 主机施加、延长、解除和清除状态。
- 状态同步 StatusId、目标、开始时间、结束时间和 Revision。
- 客户端不能自行解除权威状态。
- 救援开始、取消和完成由主机确认。
- 纯表现的表情和粒子本地播放。
- 玩家离开时取消其参与的救援。
- 全队脱困只由主机上的 Level Recovery Orchestrator 触发。
- 迟加入者获得当前有效状态快照。

## MVP范围

- 至少一种搞笑临时状态。
- 至少一种队友救援。
- 超时解除。
- 检查点恢复。
- 全队无法互救检测与事件；跨系统兜底恢复由 Level 负责。
- 与一个机关失败输出集成。
- 数据驱动状态时长、标签和救援方式。

## 非MVP范围

- 生命值、死亡和复活资源。
- 长期疾病、诅咒和负面成长。
- 复杂状态抗性和叠层数值。
- 战斗控制效果。
- 竞争性救援评分。
- 失败后的装备或资源惩罚。

## 验收标准

- 普通失败不重载整张地图。
- 状态开始、持续和解除在所有客户端一致。
- 受困玩家和队友都能通过非语音信息理解救援方式。
- 缺少特定角色时仍有通用救援。
- 状态超时或全队受困时可以安全恢复。
- 状态解除后玩家控制完全恢复，无残留锁定。
- 救援重复请求或玩家离开不会永久卡死。
- 失败平均恢复时间不破坏 10～20 分钟目标。

## 风险与待确认事项

### 风险

- 搞笑状态实际变成长时间失去控制。
- 多状态叠加造成无法恢复。
- 求救标记过多产生噪声。
- 全队脱困逻辑误判并打断正常解谜。
- 失败支线成为绕过机关的捷径。

### 待确认

- MVP 首个可救援状态的具体主题与持续时间。
- 状态是否允许叠加；建议 MVP 默认互斥或替换。
- 全队受困的判定等待时间。
- 救援是按住交互还是完成一次动作。
- 失败是否掉落普通物品及其恢复规则。
