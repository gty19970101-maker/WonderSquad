# Network Authority Rules

## 系统目标

统一 Wonder Squad MVP 的网络权威规则，确保 2～4 人实时合作中资源、能力、道具、机关、失败、救援和关卡结果唯一且一致。

采用 Photon Fusion 2 Host Mode：客户端表达意图，主机决定共享结果。

## 系统边界

负责定义：

- 输入权、状态权和表现权。
- 请求、校验、幂等和状态复制规则。
- 各系统必须由主机决定的结果。
- 可以本地处理的数据。
- 玩家离开、迟到事件和异常恢复原则。

不负责：

- 具体 Fusion API 和完整代码。
- 专用服务器部署。
- 语音音频传输。
- 账号、安全运营和复杂反作弊。
- 游戏规则本身。

## 核心流程

### 通用权威请求

```text
客户端产生意图
→ 生成 RequestId
→ 发送 PlayerId、目标 ID、输入和必要版本
→ 主机校验会话、玩家、距离、权限、状态和资源
→ 主机执行领域规则
→ 写入权威状态
→ 同步快照或结果事件
→ 客户端更新表现
```

### 状态选择

- 短暂意图：输入流或 RPC。
- 需迟加入者重建的状态：Networked Property 或快照。
- 纯表现：本地事件。
- 不允许以一次 RPC 作为持续状态的唯一来源。

### 幂等

每个会改变共享状态的请求必须：

- 有 RequestId。
- 在主机记录短期处理结果。
- 重复到达时返回既有结果。
- 不重复采集、扣料、生成、救援或完成。

## 主要状态

### 会话角色

- `None`
- `Host`
- `Client`

### 请求

- `Received`
- `Accepted`
- `Rejected`
- `Applied`
- `Duplicate`
- `Expired`

### 权威分类

- `InputAuthority`：本地玩家输入。
- `StateAuthority`：主机共享状态。
- `PresentationOnly`：本地表现。

## 与其他系统的依赖

本文件是跨系统约束，不对应一个被 Gameplay 直接引用的业务程序集。

- `Core/Contracts` 定义网络无关的命令、快照和事件。
- Network/Fusion Adapter 依赖各领域公开网络契约和 Photon Fusion 2。
- Gameplay 系统不引用 `NetworkRunner`、RPC 或 Photon 类型。
- Level 通过公开会话端口接收房间和连接事件。
- Save 只处理本地设置，不被网络会话当作权威来源。

## 联机同步要求

### 必须由主机决定

| 系统 | 主机权威结果 |
|---|---|
| Player | 最终位置、速度、跳跃合法性、击飞、恢复点 |
| Ability | 角色确认、目标合法性、能力效果、持续与冷却 |
| Communication | 标记位置、类型、频率、数量、生命周期、求救状态 |
| Inventory | 增加、预留、消耗与能力成本修饰 |
| Item | 生成、持有、放置、使用、恢复、销毁 |
| Crafting | 配方、材料、事务、输出 |
| Puzzle | 输入、状态转换、解法完成、失败输出、重置 |
| Status/Rescue | 状态施加、持续、解除、救援和疑似全队受困事件 |
| Level | 关卡、固定默认变体、开始、检查点、全队脱困、恢复事务、完成和结算 |

### 只在本地决定

- 输入设备与按键映射。
- 摄像机、插值和本地预测表现。
- UI 页面与布局。
- 语音音量、单人静音和标记过滤。
- 画质、语言和辅助功能。
- 不影响玩法的粒子、音效和装饰动画。

### 语音

- 第一阶段不集成语音 SDK，以下规则用于后续产品版本。
- 语音音频走独立语音服务。
- Fusion 只同步必要的麦克风状态图标或语义状态。
- 语音内容不存档、不回放、不参与谜题。

## MVP范围

- Host Mode。
- 2～4 人。
- 玩家输入和移动同步。
- 角色与能力。
- 标记与求救。
- 资源、库存、道具与制作。
- 三个机关。
- 临时状态与救援。
- 固定默认变体 ID、关卡阶段和完成。
- 随机种子选择实际内容不进入第一阶段。
- 请求幂等、基本弱网和争用测试。
- 主机退出时结束本局。

## 非MVP范围

- 专用服务器。
- 主机迁移。
- 复杂断线重连和长时间保留会话。
- 公开竞技级反作弊。
- 服务端持久世界。
- 大规模多人。
- 自研语音传输。
- 基础队伍语音 SDK。
- 完整状态回放系统。

## 验收标准

- 客户端无法直接改变任何共享结果。
- 两人同时操作同一对象时结果唯一。
- 重复请求不重复发放或消耗。
- 迟到事件不会覆盖更新的机关或状态 Revision。
- 迟加入者若被允许，能重建持续状态。
- 玩家离开不会造成关键道具、交互槽或救援永久占用。
- 相同种子和变体在所有客户端一致。
- 常见延迟、抖动和丢包下可以完成整关。
- 网络 SDK 类型不泄漏到大多数玩法域接口。

## 风险与待确认事项

### 风险

- 网络物理对象过多。
- 能力效果依赖不可预测物理。
- 标记和动作使用错误同步方式造成带宽浪费。
- 状态解除与迟到请求竞争。
- Host 可作弊；MVP 接受此信任边界。

### 待确认

- Fusion Tick Rate 和移动同步参数。
- MVP 是否允许中途加入。
- 断线重连等待时间。
- 标记频率、数量和生命周期的默认值。
- 请求结果缓存保留多少 Tick。
- 主机退出提示和结算策略。
